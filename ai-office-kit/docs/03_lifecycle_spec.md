# 03. 状態ライフサイクル仕様

キャラは「時刻」に応じて席・作業・休憩を自動で行き来する。基準は各メンバーの `lastActWall`
（最後に稼働があった実時刻）。`office_state.json` の `at` や実稼働検知がこれを更新する。

## しきい値
```js
const STALE_MS = 12 * 3600e3;   // 12時間。これを超えて無稼働 → 休息へ
// 「完了✓」表示は done の at から 1時間（02の反映ルール③）
```

## 内部状態（worker.state）
| state | 意味 | 遷移条件 |
|---|---|---|
| `desk` | 席で待機 | 既定。稼働検知で `live` へ / 12h無稼働で `toBreak` へ |
| `live` | 作業中 | `working` 指定 or 実稼働検知。検知が切れたら `desk` へ |
| `toBreak` | 休憩室へ歩行中 | 12h無稼働で発生。着いたら `rest` |
| `rest` | 休憩室で休息 | 新しい稼働記録が付く/12h以内に戻ると `toDesk` |
| `toDesk` | 席へ歩行中 | 復帰。着いたら `live` or `desk` |

## タイムライン（無稼働が続いた場合）
```
作業完了(at)
  │  0〜1時間   … 「完了✓」表示（席）
  │  1〜12時間  … 「待機中」表示（席でスタンバイ）
  │  12時間超   … 休憩室へ歩いて移動 →「休息中」（Zzz… / ☕）
  ▼
新しい作業記録(at更新) or 稼働検知 → 即座に席へ戻って再開
```

## 常時待機メンバー（idle:true）
- `TEAM` の該当メンバーに `idle:true` を付けると、最初から休憩室にいて、**たまに休憩室内を移動**する。
- 「今は動いていないが在籍しているメンバー」を表現するのに使う。

## 稼働率 load による滞在時間
各メンバーの `load`（0〜1）で、作業と休憩の長さが変わる（見た目の演出）。
```js
workDur(w) = 6 + w.load*22 + rand(0..6)   // load高 → 作業が長い
restDur(w) = 4 + (1-load)*24 + rand(0..6) // load低 → 休憩が長い
```
- `load` は「そのキャラがどれだけ働き者に見えるか」の演出値。実際の稼働判定は `at`/稼働検知が主。

## 歩行
- 席 ⇄ 休憩室は「ドア → 廊下(walkY) → 休憩室入口(BREAK_IN) → スポット」の経路を自動生成。
- 使う廊下は所属フロアで自動選択（`01` 参照）。歩行速度・2コマアニメは内部で処理。

## 表示の維持
- タブ非表示中は requestAnimationFrame が止まるため、状態表とJSON反映は `setInterval` で継続更新される（画面を隠しても状態はズレない）。

## 受け取り側が調整できるポイント
- `STALE_MS` を変えれば「休息に入るまでの時間」を変更可能（例：8時間にしたいなら `8*3600e3`）。
- 「完了✓」を1時間より長く出したい場合は、`02` の反映ルール③該当箇所（`3600e3`）を調整。
