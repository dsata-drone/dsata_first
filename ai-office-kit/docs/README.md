# AIバーチャルオフィス — レイアウト & システム仕様（配布版）

カイロソフト風の2.5頭身キャラが働く、Canvas製の「AIチーム稼働モニタ」の**設計仕様一式**です。
**メンバー（キャラクター）定義は含みません。** 受け取った側が自分のメンバーを入れて使えるように、
レイアウト構造・状態システム・ライフサイクル・データ連携だけを抜き出しています。

## これは何か
- 1枚のHTML（`ai_office_NN.html`）＋同フォルダの `office_state.json` で動く。
- キャラは HTML内 canvas に手描きスプライトで描画（外部画像なし）。
- `office_state.json` を書き換えると、担当キャラが「作業中→完了→休息」と自動で動く。
- サーバー不要の見た目だが、**JSON読み込みのため簡易ローカルサーバー経由で開く**必要がある（`file://` 不可）。

## 同梱ドキュメント
| ファイル | 内容 |
|---|---|
| `01_layout_spec.md` | 座標系・フロア/部屋・廊下・休憩室・ドア・机。**自分用に部屋を変える方法** |
| `02_state_system_spec.md` | `office_state.json` のスキーマと反映ルール（作業中/完了/日誌） |
| `03_lifecycle_spec.md` | 状態ライフサイクル（完了✓1h / 待機12h / 休息 / 常時待機）としきい値 |
| `04_member_schema.md` | メンバー1件のデータ構造。**自分のメンバーの入れ方**（配色・職種・持ち物） |
| `05_setup_and_serve.md` | ローカルサーバー起動・ランチャー・ダッシュボードのデータ源 |

## 最小の使い方（3ステップ）
1. `ai_office_template.html`（メンバー空のテンプレ）を用意する。
2. `04_member_schema.md` を見て `TEAM = [ ... ]` に自分のメンバーを追記。部屋名は `01` の `ROOMS` と合わせる。
3. `05` の手順でローカルサーバーを立て、ブラウザで開く。`office_state.json` を書けば動き出す。

## 設計思想（引き継ぎメモ）
- **架空の数字を出さない**：ダッシュボードは値が取れなければ「未接続/集計待ち」を表示する方針。
- **状態は時刻で自動遷移**：`office_state.json` の各エントリに付ける `at`（ISO時刻）が全ライフサイクルの基準。
- **名前が主キー**：`office_state.json` の `name` は `TEAM` の `name` と**完全一致**でないと反映されない（ここが最頻の詰まりどころ）。
